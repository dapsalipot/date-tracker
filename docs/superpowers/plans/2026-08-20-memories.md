# Memories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the app a memory — a third tab surfacing what happened a year ago, how long the couple's weekly streak runs, the milestones they've passed, and the dates they loved — plus the back-dating that all of it depends on.

**Architecture:** Four independent read models, each a small module under `src/domain/memories/`, feeding one screen. The streak is a pure function over date strings with no database at all. Back-dating extends the existing `updateDateDetails` rather than adding a parallel write path, and the date picker reuses the app's own `CalendarGrid` rather than adding a dependency.

**Tech Stack:** React Native, Expo SDK 57, expo-router, drizzle-orm over expo-sqlite / better-sqlite3, vitest.

**Spec:** `docs/superpowers/specs/2026-08-20-memories-design.md`

## Global Constraints

- `src/domain/**` must not import react, react-native or expo.
- No component may contain a raw hex colour. Colour comes from `useTheme()`; the sole sanctioned exception is `src/ui/photoOverlay.ts`.
- No `fontWeight` anywhere — the app uses a custom Nunito family where a numeric weight renders as a faux-bold smear. Emphasis comes from `theme.type.*` tokens.
- Kind colours **outline** chips and **fill** bars, never the reverse.
- Radii: `sm 8 · md 12 · lg 18 · xl 24`.
- Every new query is couple-scoped, respects `deleted_at` on dates and stops, and is proven by a mutation that must fail a test.
- A week runs **Monday to Sunday**.
- Favourites are dates rated **4 or more**.
- Future dates are rejected — this is a journal, not a planner.
- **No new dependency.** The date picker reuses `CalendarGrid`.
- Never run `npm run lint` — no ESLint config is committed and it rewrites `package.json`.

Reuse the shared feed selection so these render as ordinary date cards. `src/domain/dates/repository.ts` exports `feedDateSelection(db, scope, status?)` and `toFeedDate(row, currencyCode)` — build on those rather than writing a fresh select, so `places`, `kindSequence` and `coverUri` come along for free.

```ts
export function onThisDay(
  db: AppDatabase,
  scope: CoupleScope,
  todayLocal: string,
): FeedDate[] {
  const monthDay = todayLocal.slice(5); // 'MM-DD'

  return feedDateSelection(db, scope, 'published')
    .having(
      and(
        sql`substr(${dates.occurredOn}, 6, 5) = ${monthDay}`,
        sql`${dates.occurredOn} < ${todayLocal}`,
      ),
    )
    .orderBy(desc(dates.occurredOn))
    .all()
    .map((row) => toFeedDate(row, scope.currencyCode));
}
```

Read `feedDateSelection` first: it is a grouped query, so a post-group filter belongs in `having`, not `where`. If its shape makes that awkward, add the predicate where the builder accepts it rather than duplicating the select.

describe('weekStreak', () => {
  it('counts consecutive weeks', () => {
    const s = weekStreak(['2026-08-17', '2026-08-10', '2026-08-03'], MONDAY);
    expect(s.current).toBe(3);

  it('stops at a missed week', () => {

    const s = weekStreak(['2026-08-17', '2026-08-03'], MONDAY);
    expect(s.current).toBe(1);

  it('counts several dates in one week once', () => {

    expect(s.current).toBe(1);
  });

  it('treats Sunday and the next Monday as different weeks', () => {
    // This is the assertion that pins the Monday-start rule. Under a
    // Sunday-start week these two days share a week and this returns 1.
    const s = weekStreak(['2026-08-16', '2026-08-17'], MONDAY);
    expect(s.current).toBe(2);
  });

  it('measures to last week when this week is still empty', () => {
    // Early in a week, a couple has not been on a date yet. Showing 0 would
    // punish them for it being Monday morning.
    const s = weekStreak(['2026-08-10', '2026-08-03'], MONDAY);
    expect(s.current).toBe(2);
    expect(s.endedLastWeek).toBe(true);

  it('does not claim the streak ended when this week has a date', () => {
    const s = weekStreak(['2026-08-17'], MONDAY);
    expect(s.endedLastWeek).toBe(false);
  });

  it('keeps the longest run after the current one breaks', () => {
    // Four weeks last year, nothing since: current is 0, longest remembers.
    const s = weekStreak(
      ['2026-06-01', '2026-05-25', '2026-05-18', '2026-05-11'],
      MONDAY,

    expect(s.current).toBe(0);
    expect(s.longest).toBe(4);
  });

  it('returns zeroes for no dates at all', () => {
    expect(weekStreak([], MONDAY)).toEqual({ current: 0, longest: 0, endedLastWeek: false });
  });

  it('does not care what order the days arrive in', () => {
    const s = weekStreak(['2026-08-03', '2026-08-17', '2026-08-10'], MONDAY);

- [ ] **Step 3: Implement**

Convert each day to the Monday that starts its week, then count back. Use `Date.UTC` for the arithmetic so no local timezone can shift a boundary — the input is already a local day string, and treating it as UTC keeps the maths pure.

```ts
/** The Monday that starts the week containing `day`, as `YYYY-MM-DD`. */
function weekStart(day: string): string {
  const [y, m, d] = day.split('-').map(Number) as [number, number, number];
  const t = Date.UTC(y, m - 1, d);
  const dow = new Date(t).getUTCDay(); // 0 = Sunday
  // Monday-anchored: Sunday is 6 days into its week, not 0.
  const backToMonday = (dow + 6) % 7;
  return new Date(t - backToMonday * 86_400_000).toISOString().slice(0, 10);
}
```

Then: map every day to its week start, dedupe into a set, sort descending, and walk backwards a week at a time from this week (or last week, if this week is absent) counting unbroken steps. Track the longest run over the whole sorted set in the same pass.

`endedLastWeek` is true when the current run is non-zero and this week's start is not in the set.

import { randomUUID } from 'node:crypto';
import { dates, stops } from '@/db/schema';

function seedDatedStops(
  db: AppDatabase,
  coupleId: string,
  occurredOn: string,
  amounts: number[],
  { status = 'published', currencyCode = 'PHP' } = {},
): string {
  const dateId = randomUUID();
  db.insert(dates).values({
    id: dateId, coupleId, occurredOn, status,
    createdBy: 'u', startedAt: 1, updatedAt: 1,
  }).run();

  amounts.forEach((amountMinor, i) => {
    db.insert(stops).values({
      id: randomUUID(), dateId, sortOrder: i, kind: 'food',
      amountMinor, currencyCode, updatedAt: 1,
    }).run();
  });

  return dateId;
}

const found = (all: Milestone[], kind: Milestone['kind']) => all.find((m) => m.kind === kind);
